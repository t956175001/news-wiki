# PRD — news-wiki

## 1. 定位

**news-wiki：自动生成、可溯源的 AI 资讯维基。**

每天自动采集 AI 领域资讯，用 LLM 三阶段结构化抽取（实体 → 概念 → 关系），为每个实体生成一个**词条**。词条里每一条论断都挂着**原文证据片段 + 来源链接 + 置信度 + 抽取所用的 prompt 版本**，点击即可回溯。

### 为什么是这个产品

传统做法是「LLM 生成摘要」——输出好不好没法验证，读者只能选择信或不信。本项目反过来：**先做结构化抽取，再把每条结构化结论钉死在原文上**。这让 LLM 的输出变成可审计的数据，而不是不可证伪的文本。

### 目标受众

2026 秋招的国内技术面试官。他们会问的问题是：
- "LLM 返回的 JSON 不合法怎么办？"
- "同一个实体在不同文章里叫法不一样怎么合并？"
- "怎么知道这条关系是从哪句话抽出来的？"
- "一次抽取花多少 token、多少钱、多久？"

**本项目的每个设计都要能回答上面某一个问题。**

## 2. 核心概念

| 概念 | 定义 | 例子 |
|---|---|---|
| **Entity（实体）** | 客观存在的具体对象 | `OpenAI`(org)、`GPT-5`(product)、`Sam Altman`(person) |
| **Concept（概念）** | 抽象的主题、技术或趋势 | `混合专家模型`、`推理时扩展`、`AI 监管` |
| **Linkage（关系）** | 主语实体 →[谓词]→ 宾语（实体或概念） | `OpenAI` -[发布]-> `GPT-5`；`GPT-5` -[采用]-> `混合专家模型` |
| **Evidence（证据）** | 支撑某条实体/概念/关系的**原文片段** | "OpenAI 于本周发布了 GPT-5……" + 来源 URL |
| **ExtractionRun** | 一次完整抽取的执行记录，含每步的耗时/token/成本/状态 | — |

**关键约束**：一条 Evidence 只能指向 entity / concept / linkage 三者之一（数据库 CheckConstraint 强制）。

## 3. 页面与验收标准

### 3.1 今日简报（首页 `/`）

LLM 聚合当日抽取结果生成的简报。

**必须满足**：
- 简报正文是 Markdown，渲染后展示
- 每个结论句尾带 `[1]` `[2]` 形式的引用角标
- 点击角标滚动到底部参考文献列表，条目含标题 + 来源链接 + 发布时间
- 无当日数据时展示最近一期，并明确标注日期
- 页面顶部显示"本简报由 {model_name} 于 YYYY-MM-DD HH:MM 自动生成"（模型名取 `DailyBrief.model_name`，是当时真正回答的那个模型，不写死）

**验收**：打开首页，任选一个角标点击，能跳到对应参考文献；点该文献能打开原文。

---

### 3.2 词条页（`/entity/:id`）★ 核心

**必须满足**：
- 头部：实体名、类型 badge、别名列表、AI 生成的摘要
- 「关系」区：该实体的出边和入边，按谓词分组
- **每条关系可展开**，展开后显示：
  - 原文证据片段（高亮呈现）
  - 来源文章标题 + 可点击的原文链接 + 发布时间
  - 置信度（0-1，以进度条或数值呈现）
  - 抽取所用的 prompt key + version（如 `wiki.extract_linkages v2`）
  - 抽取的 `run_id`，可点击跳转到流水线面板对应记录
- 「首次出现 / 最近出现」时间
- 空状态：该实体暂无关系时给出友好提示，不是空白页

**验收**：任选一个实体，展开任一关系，上述五项信息全部可见且链接可点。

---

### 3.3 关系图谱（`/graph`）

**必须满足**：
- ECharts 力导向图，实体和概念为节点（用颜色区分），关系为边
- 节点大小按关系数量加权
- 支持缩放、拖拽
- 可按实体类型 / 概念命名空间筛选
- 点击节点跳转对应词条页
- 边 hover 显示谓词
- 节点数超过阈值（建议 150）时默认只展示 Top-N，并给出提示

**验收**：图能渲染出来且不卡；点任一节点能进词条页。

**降级预案**：若 D10 时间不够，降级为「实体列表 + 关系表格」，词条页的证据溯源不受影响。

---

### 3.4 流水线面板（`/ops`）

**必须满足**：
- 表格列出历次 `ExtractionRun`：run_id（截断显示）、开始时间、状态、总耗时、总 token、估算成本
- 点击展开单次 run 的分步详情：ingest / extract_entities / extract_concepts / extract_linkages / save / brief，每步的状态、耗时、token
- 失败的 run 展示 `error_message`
- 顶部聚合卡片：近 7 天总 run 数、成功率、总 token、总成本
- Prompt 版本区：列出所有 `PromptTemplate` 及其当前版本号、更新时间、模板全文（**只读**）

**验收**：`/ops` 打开能看到至少一条 run 记录，展开后各步耗时和 token 都有值。

## 4. 演示模式与成本控制

线上是公开 demo，必须防止访客烧 token。

| 措施 | 要求 |
|---|---|
| **预置数据** | `python manage.py seed_demo` 灌入 80-100 篇已抽取好的文章 + 完整图谱 + 至少 7 天简报。访客零操作即可浏览全部页面 |
| **写操作限流** | 触发抽取等写操作走 DRF `ScopedRateThrottle`，**匿名 IP 每天 3 次**。超限返回 HTTP 429 + 中文友好文案（`{"code":"RATE_LIMITED","detail":"演示模式下每个 IP 每天可触发 3 次实时抽取，明天再来试试～"}`），前端以提示条呈现，不弹报错 |
| **日预算熔断** | `LLM_DAILY_BUDGET_CNY` 环境变量。当日累计 `cost_cny` 超阈值后，所有访客触发的 LLM 入口返回只读提示，UI 顶部挂 banner。cron 任务不受此限 |
| **cron 保护** | `/api/v1/ops/cron/daily` 必须校验 `X-Cron-Token` header，与环境变量比对。访客无法触发 |

## 5. 不做清单（明确排除）

以下功能**不在范围内**，看到也不要顺手加：

- ❌ 用户注册 / 登录 / 权限系统（管理用 Django Admin 即可）
- ❌ RAG 问答 / 向量检索 / embedding（本期不做，见 `DECISIONS.md` ADR-005）
- ❌ 文件上传与解析（PDF / DOCX / Markdown）
- ❌ 标签体系（Tag / ContentTag / 标签重跑）——`Concept` 已承担分类职能
- ❌ Prompt 在线编辑（只做只读展示）
- ❌ 前端的调度器配置页（cron 交给 GitHub Actions）
- ❌ 多语言 i18n
- ❌ 移动端 App / 小程序
- ❌ 实时 WebSocket 推送（轮询足够）
- ❌ 多租户 / 团队协作
- ❌ 云端运行 Playwright（仅保留为本地可选 adapter，见 ADR-001）

## 6. 非功能要求

| 项 | 要求 |
|---|---|
| 首页首屏 | 国内 4G 网络 3 秒内出内容 |
| 单次抽取 | 一批 5 篇文章，端到端 < 90 秒 |
| API 响应 | 列表接口 P95 < 500ms（预置数据规模下） |
| 可用性 | 简历链接必须常年可打开；VPS 故障时有降级方案（见 `DEPLOYMENT.md`） |
| 浏览器 | Chrome / Edge / Safari 最新两个版本，不支持 IE |

## 7. 里程碑

见 `docs/ROADMAP.md`。硬骨头是 D4（三步抽取管线）和 D9（证据溯源展示）。

**优先级排序（时间不够时从下往上砍）**：
1. 词条页 + 证据溯源 ← **绝不能砍**
2. 三步抽取管线
3. 今日简报
4. 流水线面板
5. 关系图谱可视化 ← 最先降级
